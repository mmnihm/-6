# 会员网盘机器人

独立的 Telegram 会员文件网盘机器人。项目采用 Python + Pyrogram + SQLite，使用会员群验证权限，并将文件分别保存到两个私有 Telegram 频道（主存储与备份存储）。

## 当前版本

当前版本支持固定超级管理员 ID、会员群验证、双频道存储、私有分享链接、文件取回、公开文件目录、批量导入，以及普通账号驱动的主备份频道历史扫描。

**不包含支付、广告解锁、短链付费或任何收费接口。**

## 部署前准备

1. 创建 Telegram Bot，取得 Bot Token。
2. 创建一个会员群，并把机器人加入群内，确保机器人可以查询成员状态。
3. 创建两个私有频道（主存储频道、备份频道），把机器人设为管理员并允许发消息。
4. 将机器人部署到自己的 VPS，配置下方必填环境变量。超级管理员由 ADMIN_ID 固定指定。

## 环境变量

复制 `.env.example` 为 `.env` 并填写：

- `BOT_TOKEN`：机器人 Token
- `API_ID`、`API_HASH`：Telegram API 凭据
- `ADMIN_ID`：超级管理员的 Telegram 数字用户 ID（必填，固定管理员身份）
- `DATABASE_PATH`：SQLite 文件路径（默认 data/bot.db）

## 机器人内绑定群和频道

1. 在部署环境变量中设置 `ADMIN_ID` 为你的 Telegram 数字用户 ID；只有该 ID 对应的账号拥有超级管理员权限。启动后由该账号私聊机器人发送 `/start`。
2. 将机器人加入会员群，建议设为管理员，确保可以查询成员状态。
3. 将机器人添加为两个私有存储频道管理员，并授予发消息权限。
4. 发送 `/admin` 打开按钮管理面板，点击“绑定会员群”“绑定主频道”“绑定备份频道”，分别直接转发对应群/频道中的一条消息。
5. 发送 `/storage` 查看绑定状态。三个 ID 均保存到 SQLite，无需填写 `MEMBER_GROUP_ID`、频道 ID 或机器人用户名环境变量。

## 自动扫描主、备份频道历史资源

无需逐个转发旧文件。使用一个普通 Telegram 用户账号登录一次，让扫描器只读取主存储频道和备份频道的历史消息，并把匹配到的文件登记进 SQLite 网页目录。

1. 先把一个普通 Telegram 用户账号加入主存储频道和备份频道，确保它能查看历史消息；不需要授予管理员权限。
2. 在机器人私聊发送 `/admin`，点击“扫描账号登录”→“开始登录”，按提示输入扫描账号手机号、Telegram 登录验证码及两步验证密码（如有）。
3. 确认网站部署平台为数据库目录启用了持久化存储；登录成功后会自动保存会话，无需进入网站终端。
4. 管理员私聊机器人发送 `/scan` 开始扫描；用 `/scanstatus` 查看进度，`/scanstop` 暂停，之后再次 `/scan` 会从上次位置继续。

扫描器只读取消息信息，不下载、不转发、不删除频道原消息。它通过 Telegram 文件唯一标识匹配主、备份两边的同一资源；只有两边都匹配成功的资源才会登记为可取回文件，单边资源会跳过，避免生成失效的双备份链接。分类会优先读取消息中的“分类：名称”，否则根据文件名关键词和媒体类型自动分类。

普通账号的登录会话保存在 `DATABASE_PATH` 所在目录的 `member_cloud_scanner.session` 文件中。请保护该文件，不要上传 GitHub、不要分享给他人；丢失持久化数据后需要重新登录。验证码和两步验证密码会短暂经过机器人私聊并尝试立即删除，因此建议使用专门的扫描账号，不要使用存有重要私聊的主账号。

## 公开文件目录

机器人同时提供网页目录入口：`/catalog`。任何人都可以查看文件名称、分类并搜索目录；点击文件后会跳转到 Telegram 机器人，机器人仍会检查会员群资格，只有会员或管理员可以取回文件。

- 网页只展示文件名称、分类、媒体类型和上传日期，不展示主/备份频道 ID、频道消息 ID 或私有频道链接。
- 网页目录是公开的，请勿上传不希望公开文件名或分类的内容。
- 网页服务与机器人运行在同一进程，默认监听 `PORT` 或 `WEB_PORT`（默认 8080）；平台需将该端口映射为公网 HTTPS 地址。
- 健康检查地址：`/healthz`。

## 启动

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python main.py
```

## 超级管理员设置\n\n超级管理员由必填环境变量 `ADMIN_ID` 指定，填写 Telegram 数字用户 ID（不是用户名，也不要加 @）。普通重启、重新部署或数据库重建都不会改变管理员身份；需要更换管理员时，只修改部署平台的 `ADMIN_ID` 并重启。请勿把该变量留空或使用他人的 ID。\n\n## 文件与权限说明

- 只有会员群成员及管理员可以上传、获取文件。
- 机器人需同时具备读取会员群成员状态、向两个私有频道发送消息的权限。
- 上传成功必须同时写入主频道和备份频道；若任一频道失败，不会把该文件登记为可分享文件。
- 分享链接使用 Telegram 深链，取回时优先主频道，失败时尝试备份频道。
- SQLite 使用 WAL 模式；数据库和频道消息都应纳入 VPS 备份计划。
